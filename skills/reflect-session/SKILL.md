# Reflect on a session

Turn observed friction into the smallest useful change to the agent's environment. For a request to review proposal issues, use the [proposal workflow](../propose-convention/PROPOSALS.md); for a session reflection, continue below.

1. Read the [engineering retro](../catalog.md#session-reflection) and apply its environment-analysis checklist. Use the current session unless another is named. Read the accessible original requests, corrections, tool outcomes and review findings. With compacted or partial history, identify the missing coverage and qualify conclusions. Keep raw transcripts and private paths local.
2. Compare observations with the project's actual commands, CI, installed contracts, approved Hub rules and relevant open/closed issues and PRs, inspecting the sources relevant to each cause. Separate a missed requirement or process failure from a later product decision. A working check that was skipped needs a different correction from a missing check; an already-proposed change needs a link and new evidence, rather than another proposal.
3. Give each material lesson a disposition: already covered, project-local, shared convention, reusable skill/pointer, uncertain proposal, or discard. Use [propose-convention](../propose-convention/SKILL.md) for the home, counterexample and owner decision. Prefer an observable check for a mechanical failure and an instruction for a judgement call. Include clarification or removal of existing guidance when that is the smaller fix. Confidence comes from evidence and transfer to another project type, rather than a required number of incidents.
4. Return a short prioritized table: **evidence → decision that should change → home and next action**. Link exact proposed wording/diffs for actionable changes and explain any important candidates being skipped. For uncertainty, use the [proposal workflow](../propose-convention/PROPOSALS.md). When proposing new instruction text, apply [writing-for-agents](../catalog.md#agent-instructions), validate its references and exercise its decisions with a representative scenario before proposing adoption. State what is merely drafted, published or approved; Hub changes become shared only after Igor reviews and merges them.

For example: disappearing scroll arrows shifted content; the project now has a geometry regression test. Record that protection and assess the missing review state. Keep that screen's chosen button size with the project.

A correction noticed during delivery needs only the brief signal in propose-convention. Run the full retrospective when requested, so learning does not take over the user's active task.
