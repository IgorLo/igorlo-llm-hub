# Propose a convention

During delivery, surface a clearly reusable correction once at a natural checkpoint: the evidence, likely home and proposed next action. Continue the authorized task. A full session review is available through [reflect-session](../reflect-session/SKILL.md).

1. Identify the concrete task and the decision an agent would make differently. Compare the current hub rule with project instructions, executable configuration and applicable upstream skills. Name the projects or project types that benefit and one case where applying the rule would give a poor result.
2. Pick a home. Put product-specific behavior or an exception with the project. For a reusable policy, propose a hub convention. For a repeatable procedure with a distinct trigger and outcome, propose a skill. If an upstream skill already fits, propose a pointer and the local condition for using it.
3. Show Igor the case in chat, the recommended home, the exact proposed wording or diff, the trigger, and its effects on existing projects. Use shareable examples for the public hub. If evidence or generality is insufficient for a rule, use the [proposal workflow](PROPOSALS.md). Continue the current task under its approved rules.
4. Wait for Igor's decision on local adoption or a hub PR. When drafting agent-facing instructions, use [writing for agents](../catalog.md#agent-instructions). When a hub PR is authorized, prepare it against the current hub revision and link the reviewable diff. Igor reviews and merges hub changes. Treat the rule as shared once it reaches the approved main branch.
